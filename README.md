# Ананда Прачар

Статический интерактивный справочник на MkDocs Material. Содержимое хранится в Markdown-файлах папки `docs/`; главная страница — `docs/index.md`.

## Основной интерфейс

Пользователь начинает с пяти областей ответственности:

- Реклама;
- Контент;
- Программы;
- Забота;
- Секретарь Прачары.

Дальнейший путь строится по уровням: **направление → область работы → действие → инструкция → инструмент**. Полная база сохраняется, индексируется поиском и открывается из карточек по мере необходимости.

## Поиск информации

На каждой странице есть меню направлений и вход в полную базу. Блок «Что нужно сделать?» позволяет найти действие и перейти к раскрытой инструкции. Каталог материалов формируется из nav в mkdocs.yml; поиск в шапке индексирует содержание всей базы.

- extra.task_routes в mkdocs.yml — короткие маршруты к существующим действиям;
- overrides/ — общее меню, каталог и выбор задачи;
- docs/javascripts/navigation.js — фильтрация и раскрытие вложенных разделов при переходе по ссылке.

Содержание методики остаётся в Markdown; элементы интерфейса не переносятся в Word.

«Забота» начинается с короткого меню из пяти переходов. Начало, ведение человека, инструменты, материалы и регулярная работа открываются отдельными страницами `docs/start/care/`. Приложение, чат и справочник статусов имеют собственные страницы. Из материалов можно вернуться к исходному шагу. Старые URL с якорями направляют к новым инструкциям. Развёрнутые материалы сохранены в `docs/start/care/handbook.md`.

Справочник статусов и шаблоны строятся из кода приложения командой `node scripts/sync-care-reference.cjs`. Режим `--check` входит в публикацию и обнаруживает расхождение. Настройки города могут отличаться от стандартных.

«Программы» имеют отдельный вход в обязанности ответственного и пять рабочих входов: календарь и досуг, виды и сценарии, анонс, подготовка и завершение, качество. Каждый формат из каталога открывает отдельную организационную заготовку. Регистрация и внимание к людям — отдельные инструкции; создание анонса закреплено за организатором. Прежние подробные материалы сохранены в `docs/start/programs/handbook.md`, старые якоря направляют к новым страницам. Дополнительные встречи планируются в ритме города; одна программа в месяц — пример, а не общая норма. Каталог разделён на основные программы, темы и общение, неформальные встречи и крупные события. Инструмент оценки качества из проекта ожидает исходный материал. Переходы в программах оформлены отдельными кнопками без стрелок раскрытия; пояснения выделены серым. Дхарма деха содержит пять этапов сатсанга; Йога Нидра — предложение нового формата «Среда, чтобы выдохнуть» с семью раскрываемыми обоснованиями. Стоимость и акции остаются гипотезами.

«Реклама» использует короткую главную страницу с входами в начало, методы, гипотезы, учёт/цели и обязанности; контент открывается как самостоятельный блок. Методические страницы находятся в `docs/start/ads/`; каждый метод открывается отдельно. Старые якоря переводят на соответствующую страницу. Предыдущие материалы сохранены в `ads/handbook.md` и исключены из поиска.

«Контент» открывается отдельно на главной и в общем меню: `docs/start/social.md`. Кнопка в начале копирует полный `CONTENT_PLAN_MONTH.txt` без длинного превью. Семь коротких раскрытий ведут к съёмке, идеям, публикации, команде, ритму и площадкам. Прежний протокол `docs/start/ads/capture.md` сохранён и дополнен; старый вход из рекламы ведёт в новый раздел. Материалы включены в Word через навигацию.

Страница «Сито» содержит три раскрывающихся блока: порядок работы, сценарий из 18 реплик и парсинг в разработке. Порядок работы открыт первым: подписчики целевых сообществ → жители своего города → не более 15 добавлений в день → ожидание принятия заявки → общение по сценарию. В списке можно отдельно скопировать реплику. Кнопка сбоку и ссылка из порядка работы открывают интерактивный сценарий `docs/tools/sito.html` в одном диалоговом окне; без JavaScript ссылка открывает инструмент отдельно. На телефоне кнопка расположена над блоками. Реплики списка и инструмента обновляются согласованно.

«Сито» описано как ручное знакомство, парсинг — как будущий подбор профилей по публичной активности, а не фильтр CSV площадок. Продвижение через личный бренд уже работает; страница метода ведёт к сестре Мадувати в Telegram `@Madhuvati_ji` для начала и обучения. Монтаж и платные инструкции ожидают материалы команды; гипотезы цен и акций не являются действующими условиями программ. У секретаря этапы работы остаются отдельными страницами.

При входе в направление интерфейс показывает главную задачу из существующего описания роли, ссылки на три отдельные страницы этапов и раскрываемые первые действия. Новые элементы представления создаются в navigation.js; исходные тексты и Word-издание сохраняют общую методику.

Главная задача и три коротких регулярных действия остаются в закреплённом блоке под меню. Обязательный минимум раскрывается отдельно. Тексты задач, ритм работы и ежемесячного развития задаются в Markdown рабочих страниц и входят в Word-издание. Высота закреплённых элементов учитывается при переходах к якорям.

## Структура

- `mkdocs.yml` — тема, поиск, расширения Markdown и навигация;
- `docs/index.md` — главная карта пяти областей работы;
- `docs/start/` — интерактивные обзорные страницы направлений;
- `docs/01_...`–`docs/13_...` — полная методическая база;
- `docs/stylesheets/extra.css` — универсальные карточки, маршруты, раскрытия и современный минималистичный оранжевый дизайн;
- `Документы_системы/` — Word-издание, карта системы и генератор;
- `app/` — отдельное PWA Ananda Prachar для учёта людей и встреч;
- `site/` — результат сборки, который не хранится в Git.

Подробная модель материалов описана в [архитектуре интерактивной методички](docs/13_Разработка_системы/Архитектура_интерактивной_методички.md).

Страница анонсов использует точный `AMA_READY_PROMPT_V8.txt` из утверждённого комплекта. Превью на сайте совпадает с источником; скачивание отдаёт исходный файл. Инструкция запуска раскрывается выше общей панели копирования и скачивания. В Word включены инструкция и ссылка на полный `.txt`, без длинного интерфейсного превью.

## Источник истины

Markdown и `mkdocs.yml` остаются общим источником для сайта и Word. После изменения содержания нужно выполнить строгую сборку сайта, затем запустить `Документы_системы/build_system_doc.py`. Для явной даты сборки используйте `--build-date YYYY-MM-DD`.

## Быстрый запуск

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
mkdocs serve
```

Строгая проверка: `mkdocs build --strict`. Публикация описана в [DEPLOY.md](DEPLOY.md), правила редактирования — в [AGENTS.md](AGENTS.md).

## Приложение Ananda Prachar

PWA публикуется по адресу `https://dpolunin999-hue.github.io/Prachara/app/`. Данные и авторизация работают через Supabase. Схема базы находится в `app/supabase-schema.sql`.

Открытые аватары по явно указанным контактам загружает Supabase Edge Function `resolve-avatar` из `supabase/functions/resolve-avatar/`. Приоритет: Telegram → ВКонтакте → MAX. Фото сохраняется в Storage `person-avatars`, его адрес — в `people.photo_url`. Новая карточка запускает поиск сразу; при открытии приложения фоновая очередь повторяет поиск для карточек без фото (до 20 за запуск города, не чаще раза в сутки для контакта). Это не ночной cron: загрузка работает сразу при добавлении и при следующем открытии приложения. Вручную выбранное изображение сохраняет приоритет. Закрытые профили и недоступные фотографии отображаются инициалами. Развёртывание функции описано в `DEPLOY.md`.
