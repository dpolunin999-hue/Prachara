# Ананда Прачар

Статический интерактивный справочник на MkDocs Material. Содержимое хранится в Markdown-файлах папки `docs/`; главная страница — `docs/index.md`.

## Основной интерфейс

Пользователь начинает с четырёх областей ответственности:

- Реклама;
- Программы;
- Забота;
- Секретарь Прачары.

Дальнейший путь строится по уровням: **направление → область работы → действие → инструкция → инструмент**. Полная база сохраняется, индексируется поиском и открывается из карточек по мере необходимости.

## Поиск информации

На каждой странице есть меню направлений и вход в полную базу. Блок «Что нужно сделать?» позволяет найти действие и перейти к раскрытой инструкции. Каталог материалов формируется из nav в mkdocs.yml; поиск в шапке индексирует содержание всей базы.

- extra.task_routes в mkdocs.yml — короткие маршруты к существующим действиям;
- overrides/ — общее меню, каталог и выбор задачи;
- docs/javascripts/navigation.js — фильтрация и раскрытие вложенных разделов при переходе по ссылке.

Содержание методики остаётся в Markdown; элементы интерфейса не переносятся в Word.

«Забота» начинается с короткого меню из пяти переходов. Начало, ведение человека, инструменты, материалы и регулярная работа открываются отдельными страницами `docs/start/care/`. Приложение, чат и справочник статусов имеют собственные страницы. Из материалов можно вернуться к исходному шагу. Старые URL с якорями направляют к новым инструкциям. Развёрнутые материалы сохранены в `docs/start/care/handbook.md`.

Справочник статусов и шаблоны строятся из кода приложения командой `node scripts/sync-care-reference.cjs`. Режим `--check` входит в публикацию и обнаруживает расхождение. Настройки города могут отличаться от стандартных.

В рекламе, программах и у секретаря начало, регулярная работа и развитие также открываются отдельными страницами; поиск действий раскрывается по необходимости.

При входе в направление интерфейс показывает главную задачу из существующего описания роли, ссылки на три отдельные страницы этапов и раскрываемые первые действия. Новые элементы представления создаются в navigation.js; исходные тексты и Word-издание сохраняют общую методику.

Главная задача и три коротких регулярных действия остаются в закреплённом блоке под меню. Обязательный минимум раскрывается отдельно. Тексты задач, ритм работы и ежемесячного развития задаются в Markdown рабочих страниц и входят в Word-издание. Высота закреплённых элементов учитывается при переходах к якорям.

## Структура

- `mkdocs.yml` — тема, поиск, расширения Markdown и навигация;
- `docs/index.md` — главная карта четырёх направлений;
- `docs/start/` — интерактивные обзорные страницы направлений;
- `docs/01_...`–`docs/13_...` — полная методическая база;
- `docs/stylesheets/extra.css` — универсальные карточки, маршруты, раскрытия и современный минималистичный оранжевый дизайн;
- `Документы_системы/` — Word-издание, карта системы и генератор;
- `app/` — отдельное PWA Ananda Prachar для учёта людей и встреч;
- `site/` — результат сборки, который не хранится в Git.

Подробная модель материалов описана в [архитектуре интерактивной методички](docs/13_Разработка_системы/Архитектура_интерактивной_методички.md).

## Источник истины

Markdown и `mkdocs.yml` остаются общим источником для сайта и Word. После изменения содержания нужно выполнить строгую сборку сайта, затем запустить `Документы_системы/build_system_doc.py`. Для явной даты сборки используйте `--build-date YYYY-MM-DD`.

## Быстрый запуск

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
mkdocs serve
```

Строгая проверка: `mkdocs build --strict`. Публикация описана в [DEPLOY.md](DEPLOY.md), правила редактирования — в [AGENTS.md](AGENTS.md).

## Приложение Ananda Prachar

PWA публикуется по адресу `https://dpolunin999-hue.github.io/Prachara/app/`. Данные и авторизация работают через Supabase. Схема базы находится в `app/supabase-schema.sql`.
