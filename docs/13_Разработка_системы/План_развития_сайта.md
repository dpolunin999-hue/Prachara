# План развития сайта «Система Прачары»

## Назначение

Сайт становится основным рабочим продуктом Прачары: единым местом, где секретарь, заботник, контент-мейкер и ведущий программы быстро находят готовый порядок действий, шаблон или материал.

Источник сайта — Markdown-документы в этой базе. Сайт развивается вместе с системой Прачары и не должен превращаться в отдельную несвязанную витрину.

## Принципы

- путь человека важнее количества публикаций и внутренних документов;
- материал отвечает на вопросы: что делать, как делать и какой результат получить;
- принятые решения отделяются от предложений и гипотез;
- одна тема имеет одно основное место, остальные страницы ссылаются на неё;
- интерфейс должен быть удобен с телефона;
- новый прачарщик должен находить нужное действие за несколько минут;
- опыт юнитов возвращается в Центр и улучшает общий стандарт.

## Этап 1. Публичный запуск

**Цель:** сайт стабильно доступен по постоянной ссылке.

- [x] собрать сайт из Markdown;
- [x] настроить навигацию и поиск;
- [x] создать автоматическую сборку;
- [ ] проверить публичную ссылку с телефона и компьютера;
- [ ] выбрать понятное имя адреса;
- [ ] определить ответственного за публикацию обновлений;
- [ ] настроить резервное хранение исходных материалов.

**Готово, когда:** человек открывает ссылку без специальных доступов, страницы и поиск работают, обновления публикуются из одной основной ветки.

## Этап 2. Обязательное ядро

**Цель:** прачарщик получает минимальный комплект для начала работы.

Приоритетные материалы:

1. путь человека и три блока Прачары;
2. первые шаги секретаря, заботника и контент-мейкера;
3. обязательная инфраструктура юнита;
4. стандарт первого контакта и первого посещения;
5. обязательный чат заботы;
6. сообщество во ВКонтакте и объявление на Avito;
7. стандарт коллективной медитации;
8. базовые показатели движения людей.

Для каждого материала проверить:

- [ ] есть цель;
- [ ] понятен ответственный;
- [ ] есть пошаговый алгоритм;
- [ ] определён минимальный результат;
- [ ] приложен готовый шаблон или чек-лист;
- [ ] указан следующий связанный материал.

## Этап 3. Библиотека готовых инструментов

**Цель:** команда не придумывает типовые материалы заново.

Создать и постепенно дополнять:

- шаблоны объявлений Avito;
- шаблоны описания сообщества во ВКонтакте;
- тексты приглашений и ответов на обращения;
- сценарии сообщения после первого посещения;
- шаблон закреплённого сообщения в чате;
- карточки программ;
- чек-листы подготовки пространства;
- таблицы показателей;
- базовые изображения для скачивания.

Каждый шаблон должен открываться на странице, легко копироваться и содержать поля, которые юнит заменяет под свой город.

## Этап 4. Дизайн и удобство

**Цель:** сайт выглядит как единый продукт и помогает быстро действовать.

- утвердить цвета, шрифты, логотип и стиль изображений;
- сделать понятную главную страницу по ролям и задачам;
- выделить обязательное, рекомендуемое и требующее решения;
- использовать раскрывающиеся блоки для длинных шаблонов;
- добавить кнопки скачивания материалов;
- проверить контраст, размер текста и навигацию с телефона;
- убрать повторения и слишком длинные страницы;
- добавить иллюстрации только там, где они помогают выполнить действие.

## Этап 5. Проверка в юнитах

**Цель:** улучшать сайт по реальному применению.

Пилотный цикл:

1. выбрать несколько юнитов разного размера;
2. дать каждой роли конкретную задачу на сайте;
3. наблюдать, что человек нашёл, а где остановился;
4. собрать предложения и примеры использования;
5. исправить непонятные места;
6. отметить проверенные материалы как рабочий стандарт.

Минимальные вопросы после проверки:

- нашли ли нужный материал без помощи;
- понятно ли, что делать первым;
- хватило ли готовых шаблонов;
- что оказалось лишним;
- какого следующего инструмента не хватило.

## Этап 6. Постоянное развитие

**Цель:** сайт остаётся актуальным рабочим инструментом.

Рабочий цикл:

**Идея → решение → материал → проверка в юните → обратная связь → обновление стандарта**

Для каждого значимого обновления:

- изменить связанные документы;
- проверить внутренние ссылки;
- выполнить строгую сборку сайта;
- записать изменение в CHANGELOG;
- опубликовать новую версию;
- сообщить ответственным, что изменилось.

4. Подготовить шаблон сообщества во ВКонтакте.
5. Подготовить шаблон закреплённого сообщения для чата заботы.
