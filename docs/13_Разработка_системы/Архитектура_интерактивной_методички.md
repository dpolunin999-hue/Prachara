# Архитектура интерактивной методички

## Назначение

Сайт ведёт человека по уровням: **направление → область работы → действие → инструкция → инструмент**. Пользователь видит только тот объём информации, который нужен для текущего решения.

## Три основных направления

1. **Реклама** — новые люди узнают о практике и выходят на контакт. Контент внутри рекламы показывает жизнь сообщества и укрепляет доверие.
2. **Программы** — человек получает сильный первый опыт.
3. **Забота** — человек продолжает путь и укрепляется в практике.

**Секретарь Прачары** координирует направления, команду, показатели и развитие системы.

Это области ответственности, а не закрытые должности. Один человек может использовать любые разделы.

## Универсальная структура материала

Для новых материалов используйте столько уровней, сколько действительно нужно:

1. **Идея** — зачем существует элемент системы.
2. **Результат** — что должно измениться.
3. **Области работы** — крупные интерактивные карточки.
4. **Действия** — конкретный порядок работы.
5. **Инструкция** — как выполнить действие.
6. **Инструменты** — шаблоны, сообщения, промпты, чек-листы, ссылки и файлы.
7. **Что сделать сейчас** — ближайшее эффективное действие.

## Логическая модель

Каждый материал можно описать следующими полями:

| Поле | Назначение |
| --- | --- |
| `id` | устойчивое имя материала |
| `title` | название для человека |
| `shortDescription` | короткое описание на карточке |
| `idea` | смысл элемента |
| `result` | ожидаемое изменение |
| `children` | вложенные области и действия |
| `actions` | конкретные шаги |
| `instructions` | подробное выполнение |
| `tools` | готовые инструменты и ссылки |
| `status` | рабочий материал или черновик для наполнения |

В текущем стеке эти данные хранятся в Markdown. Заголовки задают уровни, ссылки задают связи, карточки показывают `children`, раскрывающиеся блоки содержат `instructions` и `tools`. Это сохраняет единый источник для сайта и Word.

## Универсальные элементы интерфейса

- `.direction-intro` — идея и конечный результат направления;
- `.action-cards` — области работы;
- `.material-route` — путь до конкретного действия;
- раскрывающийся блок MkDocs `???` — инструкция или инструмент;
- `.next-step` — ближайшее эффективное действие;
- `.back-button` и `.page-breadcrumbs` — возврат и контекст.

## Как пользователь находит информацию

На каждой странице доступны главная, три основных направления, секретарь и база знаний. Активный раздел выделен. Внутри материала есть путь возврата, а на телефоне дополнительно работает меню полной структуры.

На главной и в направлениях блок «Что нужно сделать?» ведёт сразу к конкретной инструкции. Действия можно найти по словам задачи или инструмента. На длинных страницах сначала показываются названия разделов; инструкция и шаблоны раскрываются по мере необходимости. Переход по ссылке автоматически открывает нужный раздел и его родительские уровни.

База знаний содержит полный каталог по разделам и поиск по названиям. Поиск в шапке ищет внутри содержания всей базы. Обзорные карты, прежние инструкции и ссылки сохраняются.

Навигация работает с клавиатуры. Кнопки и ссылки рассчитаны на касание на телефоне. Сайт сохраняет обычные ссылки и исходное содержание при отключённом JavaScript.

## Правило добавления

1. Найти существующее направление и основной Markdown-файл темы.
2. Добавить карточку или ссылку на новый уровень.
3. Создать отдельную страницу только для крупного материала.
4. Для короткой инструкции использовать раскрывающийся блок на текущей странице.
5. Добавить страницу в `mkdocs.yml`, если она должна участвовать в навигации и Word-сборке.
6. Проверить мобильный экран, поиск, ссылки и ближайшее действие.
7. Пересобрать сайт и Word-документ.

## Что не входит в текущий этап

Авторизация, личные кабинеты, роли доступа, персональные задачи, отметки выполнения, сложная аналитика и CRM сайта не реализуются на этом этапе.
